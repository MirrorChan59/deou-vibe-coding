# 得欧Vibe Coding 创意梳理工作台

帮助学生把模糊想法梳理成可执行 Web 项目创意方案的交互式工作台。本版本与妙搭原版（Vibe Coding 创意梳理工作台）功能与样式完全一致：直接从原版提取全部页面样式（31KB CSS 原样保留）、组件源码与图片资源，仅去除了妙搭平台的遥测与编辑模式外壳。

**本版新增：学生登录 + 创意方案数据上报**——老师在飞书多维表格里录入账号密码，学生用账号密码登录工作台；每个学生的填写内容在浏览器本地按账号隔离保存。学生在第 6 步点击「📤 提交给老师」，创意方案会写入老师的多维表格，老师打开表格即可统一查看全班提交。

## 功能

- 六步创意梳理流程：灵感起源 → 用户画像 → 商业调研 → 核心功能 → 方案评分 → 创意输出
- 每步大字标题 + 引导提示卡（灵感提示 / 用户思维 / MVP 原则等）
- 12 个项目类型标签、12 类目标人群标签、6 种调研方法卡片（含耗时与难度）
- 优秀 Vibe Coding 案例库（8 个案例，配图，可一键应用到自己的项目）
- 5 维度方案自检评分（优秀 ≥75 / 中等 50-74 / 待加强 <50）
- 一键生成创意方案文档，支持复制 Markdown 和下载文件
- 视觉微调面板：主题色（6 色可选）、背景主题（草稿纸 / 深色）、手写 Logo 字体开关
- **账号登录：学生在登录页输入老师发放的账号密码，校验通过才能进入工作台；支持停用账号、退出登录、7 天免登录**
- **创意方案上报：第 6 步「📤 提交给老师」一键提交，方案（项目名、姓名、账号、综合评分、项目类型、完整 Markdown）写入老师的多维表格；可修改后重复提交，每次提交生成一条新记录，保留提交历史**
- 填写内容自动保存到浏览器 localStorage（按登录账号隔离），侧栏实时完成进度
- 移动端适配

## 目录结构

```
.
├── index.html          # 页面外壳 + 全部样式（与妙搭原版一致）
├── components/         # React 组件源码（浏览器内 Babel 即时编译，无构建步骤）
│   ├── tweaks-panel.jsx  # 视觉微调面板
│   ├── steps.jsx         # 步骤 1/2/4/5/6 与案例库
│   ├── extra.jsx         # 步骤 3 商业调研等
│   ├── login.jsx         # 登录页与会话管理
│   └── App.jsx           # 主应用（状态管理、步骤切换、主题应用、登录门禁）
├── functions/
│   └── api/
│       ├── login.js    # 登录校验接口（Cloudflare Pages Function）
│       └── submit.js   # 创意方案上报接口（Cloudflare Pages Function）
├── vendor/             # react / react-dom / babel-standalone（本地化，可离线运行）
└── assets/             # logo 与 8 张案例插图
```

技术说明：React 18 UMD + Babel standalone 在浏览器端直接编译 JSX，无需任何构建工具。所有依赖已本地化到 `vendor/`。登录校验与方案上报分别由 `functions/api/login.js`、`functions/api/submit.js`（Cloudflare Pages Functions）完成，数据存放在老师的飞书多维表格中，凭证通过环境变量配置，不会出现在前端代码里。

## 本地预览

需要通过静态服务器打开（浏览器不允许 file:// 加载 JSX）：

```bash
python3 -m http.server 8000
# 打开 http://localhost:8000
```

注意：本地预览没有登录后端（`/api/login` 不存在），会显示登录页但无法真正登录；登录功能需部署到 Cloudflare Pages 并完成下方配置后生效。

## 登录功能配置（一次性，约 10 分钟）

登录需要三个要素：① 飞书多维表格（账号数据） ② 飞书自建应用（读取表格的凭证） ③ Cloudflare 环境变量（把凭证交给后端）。

### 第 1 步 · 录入账号到多维表格

打开学生账号表（已经建好）：

https://my.feishu.cn/base/QSyHbnLnXaWlKZsESrKcQzS2ndd

每行一个学生：填写「账号」「密码」「姓名」，「状态」选 **启用**。停用时把状态改成「停用」即可，该行学生立即无法登录。

注意：密码以明文存放在这张表里，请保持表格「仅自己可见」，不要分享给他人。

### 第 2 步 · 创建飞书自建应用（拿到读取表格的凭证）

1. 打开 https://open.feishu.cn/app ，登录后点「创建企业自建应用」，名称随意（如「工作台登录」）
2. 进入应用 → 「凭证与基础信息」，记下 **App ID** 和 **App Secret**
3. 左侧「权限管理」→ 搜索并开通权限：**`bitable:app`**（查看、评论、编辑和管理多维表格——上报功能需要写入记录，只读的 `bitable:app:readonly` 不够用）
4. 左侧「应用发布」→ 创建版本并发布（个人版直接发布即可，无需审批）

> ⚠️ **已按旧版 README 配置过只读权限的老师**：请到「权限管理」把 `bitable:app:readonly` 升级为 `bitable:app`，然后**重新创建版本并发布**，否则学生提交会失败（登录不受影响）。

### 第 3 步 · 授权应用访问这张表格

打开学生账号表 → 右上角「···」→「更多」→「添加文档应用」→ 搜索刚创建的应用并添加（授予「可编辑」——上报功能要向同一张多维表格的「学生创意方案」表写入记录）。

> 应用授权对整个多维表格生效，同一张表里的「学生账号」「学生创意方案」两个数据表都自动覆盖，无需重复授权。

### 第 4 步 · 在 Cloudflare 配置环境变量

进入 Cloudflare Pages 项目 → Settings → Environment variables → 添加三个变量（Production）：

| 变量名 | 值 |
|---|---|
| `FEISHU_APP_ID` | 第 2 步的 App ID |
| `FEISHU_APP_SECRET` | 第 2 步的 App Secret |
| `AUTH_SECRET` | 一段随机长字符串（会话签名密钥，可用密码生成器生成 32 位以上） |

`BASE_TOKEN` 和 `TABLE_ID` 已内置默认值（对应第 1 步那张表），一般不用配。

### 第 5 步 · 重新部署

环境变量改完需要重新部署才生效：Pages 项目 → Deployments → 最新部署右侧「···」→ Retry deployment；或者重新上传一次代码。

完成后打开站点：学生会先看到登录页，用表格里的账号密码即可进入。

## 创意方案上报（老师统一查看）

学生端：登录后完成六步梳理，在第 6 步「创意输出」页点击顶部「📤 提交给老师」。提交成功会显示「✓ 已提交」；修改内容后可再次点击提交，每次提交生成一条新记录，完整保留提交历史。

老师端：打开多维表格，切到「学生创意方案」数据表即可统一查看全班提交：

https://my.feishu.cn/base/QSyHbnLnXaWlKZsESrKcQzS2ndd

每条记录包含：项目名称、姓名、账号、综合评分（0-100）、项目类型、创意方案（完整 Markdown 全文）、提交时间（自动记录）。可以直接在表格里按评分排序、按姓名筛选，或开「表单视图」之外的任意视图做讲评。

配置说明：

- **无需新增环境变量**——上报复用登录的三个变量（`FEISHU_APP_ID` / `FEISHU_APP_SECRET` / `AUTH_SECRET`），`SUBMIT_TABLE_ID` 已内置默认值（对应「学生创意方案」表）。
- 唯一要做的：确认第 2 步的权限已从 `bitable:app:readonly` 升级为 **`bitable:app`** 并重新发布应用版本（见上方 ⚠️ 提示），第 3 步的文档应用授权为「可编辑」。
- 学生提交时服务端会校验登录会话签名，未登录或会话过期（超过 7 天）会被拒绝并提示重新登录。
- 更新代码到 Cloudflare 后记得重新部署（Retry deployment 或重新上传）。

### 安全边界说明（如实告知）

- 密码校验在 Cloudflare 服务端完成，飞书凭证只存在环境变量里，前端代码不含有任何密钥。
- 登录签发的是 7 天有效的本地会话，用于界面门禁与提交鉴权；学生的过程填写数据保存在各自浏览器本地（localStorage），只有点击「提交给老师」时才会把最终方案写入老师的多维表格。同一台电脑不同账号登录，数据互相隔离。
- 这套方案适合课堂场景；不要把账号表分享出去，也不要复用学生在别处使用过的密码。

## 部署到 Cloudflare Pages

方式一：GitHub 集成（推荐）

1. 把本目录推送到 GitHub 仓库（`index.html` 放在仓库根目录）
2. Cloudflare Dashboard → Workers & Pages → Create → Pages → Connect to Git
3. 选择仓库，构建设置：
   - Framework preset：**None**
   - Build command：**留空**
   - Build output directory：**`/`**（根目录）
4. 点击 Save and Deploy，完成后即可获得 `*.pages.dev` 域名

方式二：直接上传

1. Cloudflare Dashboard → Workers & Pages → Create → Pages → Upload assets
2. 把本目录整个拖入上传即可（`functions/` 目录会被自动识别为 Pages Functions）
